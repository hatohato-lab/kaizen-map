# 発見レンズ — 工程③「深掘り」の手順書（AI向け）

あなた（Claude等のAI）は、kaizen-map の survey レポートで★が付いた区画を1つ受け取り、
**種類を限定せずに**改善候補を探して JSON に書き出す。

## 入力

- 対象区画のフォルダパス（★が付いた区画から人間が選ぶ）
- survey レポート（全体地図・兆候）— 認識合わせのために先に読む

## 手順

1. 区画のファイル一覧を眺め、まず構造を把握する（いきなり全ファイルを読まない）
2. 入口（README等）→ 主要ファイルの順に読む。大きい区画は代表を選んで読む
3. 気づいた改善候補を、**種類を決めつけずに**挙げる。例：
   - 重複（同じ内容・同じ役割のものが2か所にある）
   - 名前と実態のズレ（ファイル名・フォルダ名が中身と合っていない）
   - ドキュメントの腐り（書いてあることが実態と違う・リンク切れ）
   - 入口の欠如・構成の迷子（どこから読めばいいか分からない）
   - 手作業の繰り返し（自動化・テンプレート化できる作業の痕跡）
   - 休眠・宙ぶらりん（作りかけで放置。続けるか閉じるか判断が要る）
   - 上記以外の何でも（このリストは例であって枠ではない）
4. 出力フォルダに `findings-<区画名>.json` を書く
5. `python kaizen_map.py <対象> -o <出力> --survey` を再実行してレポートに合流させる

## 出力の形式（厳守）

```json
[
  {"path": "<区画>/<根拠となるファイルやフォルダ>", "text": "<何が・なぜ改善候補か。1〜2文>"},
  ...
]
```

## 守ること

- **根拠パス必須**。パスを示せない指摘は書かない（曖昧な一般論の禁止）
- **問題が無い場所に無理に赤を付けない**。指摘ゼロは正当な結果
- 指摘は全件「推定」として扱われる。断定の口調で書かない
- 件数は多くても10件程度。数より、人間が判断できる具体性を優先する
- 対象の中に個人情報・秘密があっても、findings に**値を書き写さない**（パスと種類だけ書く）
